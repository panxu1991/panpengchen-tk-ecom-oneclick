# 短视频方法论整体纲领（脚本 + 图片 + 成片，一套约束）

> **定位**：本文件是短视频的「宪法/纲领」，约束下面三个环节——脚本怎么出、图片怎么生成、成片怎么执行。`xianyu110/ecommerce-video-skills` 只是**执行器**（storyboard → ffmpeg 渲染），方法论由本纲领统一约束，不能各自为政。

## 一、一条主线：5-beat 结构（所有脚本/分镜都套它）

```
Hook(0-3s 钩子) → Problem(3-5s 痛点) → Solution(5-8s 方案) → Proof(8-13s 证明) → CTA(13-15s 转化)
```
- 每镜 2-3 秒，总时长 15-30 秒，9:16 竖屏。
- 钩子决定前 3 秒留人，CTA 决定转化，中间三拍是「说服」。

## 二、脚本层（本 SKILL 出，方法论约束）

- 15 AI 脚本：六要素（画面/口播/字幕/风格/BGM/比例），每个脚本一个核心卖点，前 3 秒有钩子、末尾有 CTA。
- 5 真人脚本：拍产品实拍图 → AI 生成 → 剪辑，执行人员可照拍。
- 变量复制：角度 × 场景 × 情绪 × 人物，换变量批量出脚本。
- **脚本必须可转成 storyboard**（每句口播对应一个镜头 + 时长），否则无法成片。

## 三、图片层（本 SKILL 出，铁律约束）

1. **AI 出图不出字**：AI 只出无字底图，文字一律 PIL 程序化叠越南语（音调零错误）。
2. **产品只用真实图抠白**：AI 绝不凭空画产品（瓶身文字会乱码 → 山寨感）。
3. **真人图用真实素材优先**：真人感图优先用实拍/真实人物参考，AI 生成人物只做「无字场景底图」。
4. 越南语文案先 underthesea 分词校验，再叠字。

## 四、成片层（xianyu110 执行）

```
脚本 → selling-point-storyboard → storyboard.json
     → image-to-video-shots（图生视频，可选；无则 Ken Burns 兜底）
     → ai-voiceover-edge-tts（越南语 vi-VN-HoaiMyNeural）
     → multilingual-dubbing（多语言本地化改写，非直译）
     → ffmpeg-auto-assemble（assemble.py 一键成片）
     → platform-spec-export（抖音/TikTok Shop/视频号/小红书/淘宝/Amazon）
     → cover-title-ab（封面 A/B）
```
- 执行器脚本在本 SKILL `scripts/video/`（9 个 py），技能说明在 `references/video-skills/`（13 个目录）。
- 依赖：`pip install pillow numpy edge-tts` + ffmpeg（含 libass）+ CJK 字体。

## 五、两个 AI 生成问题的解法（硬规则）

### 问题 1：人物结构性错位（多手指/肢体错位/五官崩）

| 优先级 | 做法 | 原理 |
|---|---|---|
| 首选 | **真实产品图 + Ken Burns 运镜**（不生成人） | 零人物生成，零错位 |
| 次选 | **真人实拍视频片段**当素材，不 AI 生成人 | 真人不崩 |
| 兜底 | 图生视频时用「商品一致性锁」：参考图锁真实抠白图 + 提示词锁形状/颜色/Logo | 减少漂移 |
| 检查 | 成片后人工抽帧看手指/肢体/五官，异常即弃用该镜头 | 人肉兜底 |

**铁律**：人物镜头宁可用「实拍 + Ken Burns」也不 AI 硬画人；AI 生成人物只做背景氛围，不做主体特写。

### 问题 2：视频内容与实际产品不符（产品变了/文字乱码/场景不符）

| 优先级 | 做法 | 原理 |
|---|---|---|
| 首选 | 产品镜头**用真实抠白图做 Ken Burns**（不是图生视频） | 产品 100% 一致 |
| 次选 | 图生视频参考图锁「真实产品抠白图」，提示词写「keep product exactly as reference」 | 减少漂移 |
| 检查 | 成片后 OCR 抽帧核对瓶身/包装文字（复用本 SKILL 的 Windows OCR 方法），乱码即弃用 | 防山寨感 |
| 兜底 | 每个分镜有「本地 Ken Burns 兜底」：图生视频失败/漂移时退回真实图运镜 | 永不空镜 |

**铁律**：成片里的「产品特写」必须来自真实图；AI 只生成「背景/场景/氛围」，不生成产品本体。

## 六、纲领 vs 执行器 的分工

| 层 | 谁 | 负责 |
|---|---|---|
| 方法论 | 本纲领 + content-video.md + 内容策略 | 5-beat 结构、脚本六要素、卖点提炼、钩子/CTA、图片铁律、AI 问题解法 |
| 执行 | xianyu110（scripts/video） | storyboard 渲染、edge-tts 配音、ffmpeg 成片、平台导出、封面 AB |

**约束关系**：执行器只吃「符合纲领的 storyboard + 符合铁律的素材」；凡违反纲领（AI 画产品、图上叠字、人物硬画）的输入，执行器可以拒收。
